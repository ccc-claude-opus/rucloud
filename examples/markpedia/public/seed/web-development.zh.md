## 概述

**網頁開發**（web development）是在瀏覽器與伺服器兩端建構網站與線上應用的技術工作，前端負責呈現與互動，後端負責資料處理與商業邏輯。其基礎是三層技術標準：HTML 描述結構、CSS 控制樣式、JavaScript 處理行為，並以 HTTP 作為前後端交換資料的主要協定。

## 從公開網路到現代框架

網頁技術的關鍵節點集中在 1990 年代中期到 2020 年代初，這段時期的變化決定了今日前端與後端的分工方式。每一項新技術都降低了實作成本，同時也提高了對效能與安全的期待。下表整理這些里程碑及其影響。

| 年份 | 里程碑 | 影響 |
| --- | --- | --- |
| 1991 | 第一個公開網站上線 | 網際網路由研究網路走向公眾服務 |
| 1993 | Mosaic 瀏覽器與 HTML 1.0 | 網頁觸及非科學家使用者 |
| 1995 | JavaScript 釋出 | 瀏覽器首次具備腳本能力 |
| 1997 | HTTP/1.1 與 CSS 1 | 傳輸與樣式標準化 |
| 2004 | Web 2.0 與 Ajax 廣泛應用 | 頁面可局部更新，社群型網站興起 |
| 2015 | HTTP/2 標準化 | 單一連線多重串流，減少交握次數 |
| 2022 | HTTP/3（QUIC） | 以 UDP 為基礎，支援 0-RTT 與 1-RTT 握手 |

## 前端渲染管線與效能指標

瀏覽器收到 HTML 後，依序經過解析、建立 CSSOM、組出渲染樹、版面配置（layout）與繪製（paint）才呈現畫面；其中受阻塞的資源與長任務是延遲主因。Google 提出的核心網頁指標要求：最大內容繪製時間（LCP）不超過 2.5 秒、互動至下次繪製時間（INP）不超過 200 毫秒、累積版面位移（CLS）不超過 0.1，作為線上服務品質的量化門檻。

## 後端介面與狀態碼

後端多以 REST 風格提供資源介面，語意由 HTTP 方法（GET、POST、PUT、DELETE）與狀態碼共同表達，例如 201 表示已建立、404 表示資源不存在、429 表示請求過多。實務上常加上 Cache-Control 標頭控制快取，並以 gzip 或 Brotli 壓縮回應內容，文字內容通常可壓縮至原始體積的 20 % 至 30 %，直接減少傳輸時間與流量成本。
